## Терминология

**Abstraction (абстрактность кода)** — степень приближенности кода к языку предметной области, в которой он оперирует; достигается при помощи выделение ключевых элементов логики кода в отдельные переиспользуемые фрагменты с целью сокрытия несущественных деталей.

**Composition (компоновка кода)** — подход к формированию кода из независимых и заменяемых компонентов, собранных в единую логику исполнения.

**Coupling (внешняя связность)** — степень зависимости между компонентами кода.

**Cohesion (внутренняя связность, цельность)** — степень, в которой реализация класса (поля, методы) связана с его назначением. Т.е. высокая цельность - когда методы класса решают задачи, соответствующие назначению класса, логика не смешана - класс не является "мультитулом"

## 1. Абстракция (Abstraction)

**Суть метода:**
Абстракция позволяет скрывать детали реализации за простым и понятным интерфейсом. Это помогает уменьшить сложность использования, облегчает расширение и модификацию кода.

**Пример до применения абстракции (без интерфейса):**
```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def draw(self):
        print(f"Рисуем круг с радиусом {self.radius}")

class Square:
    def __init__(self, side):
        self.side = side

    def draw(self):
        print(f"Рисуем квадрат со стороной {self.side}")

circle = Circle(5)
square = Square(4)
circle.draw()
square.draw()
```

**Пример после применения абстракции (с использованием абстрактного базового класса):**
```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def draw(self):
        pass

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def draw(self):
        print(f"Рисуем круг с радиусом {self.radius}")

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def draw(self):
        print(f"Рисуем квадрат со стороной {self.side}")

# Теперь можно работать с любыми объектами, реализующими интерфейс Shape единообразно:
shapes = [Circle(5), Square(4)]
for shape in shapes:
    shape.draw()
```

**Преимущества:**
- Упрощение кода за счёт скрытия деталей реализации.
- Возможность добавлять новые фигуры, не меняя основной логики работы с ними.

## 2. Связность (Coupling)

**Суть метода:**
Связность определяет степень зависимости между компонентами системы. Чем ниже связность, тем легче модифицировать и тестировать отдельные компоненты, так как изменения в одном модуле меньше влияют на другие.

**Пример до (жесткая связь между классами):**
```python
class Payment:
    def pay(self):
        print("Обработка платежа...")

class Order:
    def __init__(self):
        # Жёсткая зависимость: класс Order сам создаёт экземпляр Payment
        self.payment = Payment()

    def process_payment(self):
        self.payment.pay()

order = Order()
order.process_payment()
```

**Пример после (ослабленная связь с использованием внедрения зависимостей):**
```python
class Payment:
    def pay(self):
        print("Обработка платежа...")

class Order:
    def __init__(self, payment_processor):
        # Зависимость передаётся извне
        self.payment_processor = payment_processor

    def process_payment(self):
        self.payment_processor.pay()

payment_processor = Payment()
order = Order(payment_processor)
order.process_payment()
```

**Преимущества:**
- Легко заменить или модифицировать компонент `Payment`, не затрагивая логику класса `Order`.
- Упрощается модульное тестирование, так как можно подменять зависимости мок-объектами.

## 3. Компоновка (Composition)

**Суть метода:**
Компоновка (composition) – это подход к формированию кода, при котором поведение класса строится за счёт включения (композирования) других объектов, а не через наследование. Такой подход обеспечивает большую гибкость и возможность заменять компоненты.

**Пример до (использование наследования, что может привести к жесткой связи):**
```python
class Engine:
    def start(self):
        print("Двигатель запущен")

class Car(Engine):  # Наследование, что заставляет Car зависеть от Engine
    def drive(self):
        self.start()
        print("Машина едет")

car = Car()
car.drive()
```

**Пример после (использование композиции):**
```python
class Engine:
    def start(self):
        print("Двигатель запущен")

class Car:
    def __init__(self, engine):
        self.engine = engine  # Композиция: Car использует объект Engine

    def drive(self):
        self.engine.start()
        print("Машина едет")

engine = Engine()
car = Car(engine)
car.drive()
```

**Преимущества:**
- Объект `Engine` можно использовать в других классах, а также легко заменить на другой вариант двигателя.
- Уменьшается жесткая зависимость между классами, что способствует повторному использованию кода.

## 4. Цельность (Cohesion)

**Суть метода:**
Цельность (cohesion) отражает, насколько элементы внутри класса или модуля относятся к единой функциональной задаче. Высокая цельность означает, что класс выполняет строго определённую задачу, что облегчает его поддержку и тестирование.

**Пример до (низкая цельность – класс выполняет разноплановые задачи):**
```python
class DataProcessor:
    def load_data(self):
        print("Загрузка данных...")

    def process_data(self):
        print("Обработка данных...")

    def send_email(self):
        print("Отправка email...")
```

**Пример после (разбиение на классы с высокой цельностью):**
```python
class DataProcessor:
    def load_data(self):
        print("Загрузка данных...")

    def process_data(self):
        print("Обработка данных...")

class EmailService:
    def send_email(self):
        print("Отправка email...")

# Использование:
processor = DataProcessor()
processor.load_data()
processor.process_data()

email_service = EmailService()
email_service.send_email()
```

**Преимущества:**
- Каждый класс отвечает за свою задачу, что упрощает понимание и поддержку кода.
- Тестирование отдельных компонентов становится проще, так как они имеют чётко определённую ответственность.

---

Эти методы помогают создавать гибкий, легко поддерживаемый и расширяемый код, что особенно важно при работе над большими проектами.
